# 领域认知笔记：适航文件体系（Week 2 任务）

> 学习目标：建立「规章(CCAR) — 程序文件(AP) — 咨询通告(AC)」三层文件体系概念，
> 能向人讲清这三层各自的定位与关系。这是理解本项目 RAG 语料和 MOC 知识来源的前提。
> 读完请结合 RESOURCES.md 中的 CCAR-21 官方链接核对原文。

## 一、三层文件体系：法规 → 程序 → 方法

审定工作里能查到的文件不是杂乱堆放的，而是一个金字塔：

| 层 | 中国 CAAC | 定位 | 强制性 | 例子 |
|----|-----------|------|--------|------|
| 1 规章 | **CCAR**（部） | 规定"必须达到什么标准"，是法律层面的要求 | 强制 | CCAR-25《运输类飞机适航标准》、CCAR-21《民用航空产品和零部件合格审定规定》 |
| 2 程序文件 | **AP**（审定程序） | 规定"按什么流程证明达标"，描述审定活动的组织与步骤 | 审定中必须遵循 | AP-21-AA-2011-03《航空器型号合格审定程序》 |
| 3 咨询通告 | **AC** | 给出"普遍认可的符合方法"，但不排斥其他等效方法 | 推荐 | 各类具体技术问题的符合性方法指引 |

记忆口诀：**CCAR 管标准，AP 管流程，AC 管方法**。

一句话理解关系：型号合格审定（TC）的依据是 CCAR-21 及相关适航标准（CCAR-23/25 等）；
审定怎么组织、查什么、谁签字，看 AP-21；某个具体条款怎么满足可以参考 AC——
但 AC 不是唯一路径，申请人可以用自己的等效方法（需审定当局认可）。

## 二、CCAR-21 目录结构概述

CCAR-21《民用航空产品和零部件合格审定规定》是**审定程序的母法**——
本项目"符合性矩阵"工作的法律起点。全文按"部(Subpart) → 章 → 条(§) → 款"组织，主线条目：

- **总则**：适用范围、定义、保密等
- **型号合格审定 / 型号认可**：TC（国产新产品）、VTC（进口产品认可）——
  本项目「编矩阵」功能服务的主战场
- **补充型号合格审定 / 改装设计批准**：STC / MDA（对已审定产品的改装）
- **生产许可审定**：PC（批量生产质量系统）
- **零部件制造人批准书**：PMA（零部件）
- **适航证件**：标准适航证、特殊适航证、限用适航证等（单机层面）
- **特许飞行**：未取得适航证时的飞行许可
- **附则**：废止与生效

> 精读建议：不必逐条读，只看目录 + 每部第一条"适用范围"，建立"哪类事找哪个部"的索引能力。
> 第 1 阶段做 RAG 切分时，规章正是按「部 → 分部 → 条 → 款 → 项」层级建元数据的。

**条款编号读法**（RAG 引用溯源的格式基础）：

```
CCAR-25.813(b)(2)
       │    │   └─ 项：具体要求点
       │    └───── 款：条下的分点
       └────────── 条：§25.813「出口通道」这类具体规定
```

## 三、中美欧三方对应关系（reg_diff 功能的领域基础）

| 层次 | 中国 CAAC | 美国 FAA | 欧洲 EASA |
|------|-----------|----------|-----------|
| 法律/法规 | CCAR（如 CCAR-25-R4） | 14 CFR / FAR（如 FAR Part 25） | Regulation (EU) No 748/2012 基础法规 |
| 适航标准 | CCAR 各部正文 | FAR 各部正文 | **CS**（Certification Specifications，如 CS-25） |
| 程序/指令 | AP（如 AP-21） | Order（如 Order 8110.4） | ——（程序并入 AMC 体系） |
| 符合方法 | AC 咨询通告 | AC（如 AC 21-10，MC 体系的历史源头） | **AMC & GM**（可接受符合方法与指导材料） |

关键事实（本项目数据创新的依据）：**CCAR-25 与 FAR Part 25 条号天然对齐**（25.813 两边都是
"出口通道"），因为 CCAR-25 早期版本即参照 FAR 修订；EASA CS-25 大框架同源。同条号三方对比
（reg_diff）因此可行，但具体技术要求存在差异（如延程运行、最新修订的引入时差）——
这正是对比功能的价值所在。

## 四、MC0–MC9 速览（第 2 阶段结构化，此处先混个脸熟）

MC = Means of Compliance（符合性验证方法），体系定义于 **AP-21 审定程序**（源头是 FAA AC 21-10）：

| 组 | 方法 |
|----|------|
| 描述类 | MC0 符合性声明 / MC1 说明性文件 |
| 分析类 | MC2 分析计算 / MC3 安全评估 |
| 试验类 | MC4 实验室试验 / MC5 地面试验 / MC6 飞行试验 / MC8 模拟器试验 |
| 检查/鉴定 | MC7 航空器检查 / MC9 设备鉴定 |

选择逻辑示例：「飞行特性类条款倾向 MC6（飞行试验）」；「材料强度要求可用 MC2（分析计算）
+ 抽样 MC4（实验室试验）佐证」。第 2 阶段将把这张表结构化为工具知识库。

## 五、与本项目的关系（为什么第 0 周期就要懂这些）

1. **RAG 语料边界**（第 1 阶段）：入库对象是第 1、2 层的公开文件（CCAR/FAR/CS + AP + AC）
2. **引用溯源格式**：回答标注 `CCAR-25.813(b)`，依赖条款层级元数据——笔记第二节的编号读法
3. **moc_suggest 的知识锚点**（第 2 阶段）：MC0–MC9 的定义与选择启发式来自 AP-21，不是 LLM 自由发挥
4. **免责边界的领域依据**：审定结论只能由审定人员/机构作出——AI 是辅助，human-in-the-loop
